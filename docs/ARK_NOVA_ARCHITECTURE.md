- `card-zones.ts`: 덱 드로우, 시장의 빈 슬롯 유지, 전체 턴 후 시장 보충, 손패 버리기. 원자적 후보 상태 안에서만 사용하는 도메인 연산이다.
- `solo-break.ts`와 `income.ts`: 기부 점유, 손패 3/5장, 행동 토큰 정리, 직원 복귀와 공급, 시장 두 장 교체, 매력·매점 기본 수입. 후원/활성 보너스 수입 효과가 끝났다는 서버 판단 전에는 다음 라운드로 넘어가지 않는다. 기본 수입과 후원 수입 효과 큐를 game.ts에 연결했다. 프로젝트 지원으로 해금되는 수입 보너스는 남아 있다.
- `goals.ts`와 `final-scoring.ts`: 원본 최종 목표와 종료 시 후원자 효과를 계산하고 트랙 상한과 승점을 반영한다. `game.ts`에서 최종 목표 버리기 선택과 종료 전이에 연결했다. 전체 카드 플레이 이후의 실제 종료 검증은 남아 있다. 참고 목록에서 빠졌던 251의 곰 종료 점수도 Glossary에 따라 처리한다.
- `game.ts`: 준비·행동·휴식·최종 목표 선택·종료를 하나의 서버 canonical state와 명령 진입점으로 연결했다. 현재 연결 명령은 초기 손패 선택, X 획득, 자금 조달 I/II, 카드 드로우/스냅 I/II, 건설 I/II, 지도 보너스·업그레이드 선택, 협회 I 일반 업무·보상 선택, 동물/후원 카드 행동과 일반 효과 선택, 버릴 카드/최종 목표 선택이다. 전체 덱을 보존하고 미구현 행동·효과 상태는 거절한다. actor·revision·단계·선택 ID를 검사하고 후보 상태만 반환한다. 이는 application의 실제 세션 인증·commit 연결을 대신하지 않는다.
- shared `solo-contracts.ts`: 솔로 대기 선택·정산·화면 전달 상태의 strict 계약. `projectArkSoloGame`은 이 계약으로 검증하며 덱 순서·미공개 목표·버린 카드의 내용을 전달하지 않는다. 기존 `contracts.ts`의 다인용 초안과 구분하며 아직 플랫폼 snapshot에 등록하지 않았다.
- `build-turn.ts`와 shared `build.ts`: 건설 중 남은 강도·면·종류, 지도 보너스 대기 선택을 저장한다. 비용을 먼저 차감하고 보너스를 해결한 뒤 다음 건설을 허용한다. 행동 도중 업그레이드해도 해당 행동은 시작 시 면을 유지한다. 지도 카드 보너스는 평판 범위의 시장/덱에서 고른다. 파빌리온 매력과 전체 땅 덮기 보너스, 건설 지도 저장 검증을 포함한다. 동물이 아직 플레이되지 않으므로 특수 우리 완공 시 동물 이동은 후속 연결 대상이다.
- `association.ts`와 shared `association.ts`: 협회 I의 평판·제휴·대학 업무, 직원 반복 비용과 공급 소유권을 연결했다. 대학 손패 상한·연구 아이콘·슬롯 보상과 평판 트랙 보상은 일반 REWARD 선택 큐로 처리한다. 미해결 보상이 있으면 행동 이동·턴 종료를 지연한다. 협회 II·보전 프로젝트·기부는 아직 거절한다.
- `association-work.ts`: 협회 I/II 일반 업무의 순차 처리 커널. 시작 시 강도와 면을 고정하고, 서로 다른 업무의 강도 합산·직원 배치, 제휴 세 번째/네 번째 슬롯 보상, 업무 후 최대 한 번의 기부와 비용 차감을 후보 상태로 반환한다. 호출 측에서 반환 보상 전부를 해결해야 다음 업무·기부·종료를 허용한다. 종료 함수는 행동 카드만 이동하며 솔로 턴을 진행하지 않는다. 보전 보너스 타일·프로젝트와 세션/활성 행동/선택 revision 연결 전이므로 이 커널의 II 기능은 아직 game.ts 명령에 노출하지 않는다.
- `animal-housing.ts`: 빈 표준/특수 우리의 수용 조건과 점유, 방사/이동 시 최소 크기 우리 후보, 무리 동물의 공유 조건. 카드 비용·아이콘 조건·행동 횟수·실제 카드 이동은 card-play/zoo-card-work 및 game.ts 명령에서 처리한다.

## 남은 전체 게임 구현

협회 II·보전 프로젝트·기부, 배수·추가 행동, 조건성 후원 훅과 프로젝트 활성 수입, 일반 건설 특수 우리 이동을 연결해야 한다. 전체 카드의 즉시·지속 효과 및 순서, 전체 효과 적용 후 최종 점수의 원본 규칙 감사도 필요하다. 또한 application의 세션 인증·직렬화·idempotency·원자 commit, 게임 전체 allowlist projection, room lifecycle·재접속·Socket.IO와 실제 플레이 화면 연결이 필요하다. 개별 도메인 함수의 테스트 통과는 실제 대국 완주를 의미하지 않는다. 기존 `Room`·`Session`·서버 권위형 경계를 유지한다.

참고 카드 데이터는 실행 가능한 규칙 엔진이 아니다. 원본 카드의 누락 수치와 조건을 교차 검증한 뒤 사용해야 한다. `464`의 바위 조건은 원본 카드 이미지 대조 후 0으로 확인했으며, `256`의 누락 매력 4도 수정했다. 프로젝트 슬롯 조건, 최종 목표, 특수 건물 형태도 최종 감사 대상이다.

## 시각·소리·상호작용

자체 생성한 동물원 전경과 여섯 생태군 일러스트를 사용한다. 생태군 그림은 각 카드 종의 개별 초상이 아니며 카드에 그 용도를 표시한다. 본게임에서는 종별 아트 보강이 필요하다. 텍스트는 HTML, 지도는 SVG다. 클릭/탭으로 기준 칸을 고른 뒤 회전·반전하고 명시적 버튼으로 확정한다. 방향키, Enter, R, F, Escape와 native dialog를 지원하고 reduced-motion을 존중한다.

- 반복마다 비용·X 토큰을 별도로 지불한다. 행의 기본 강도는 반복 시작 때 고정하고, 각 실제 행동은 그때의 업그레이드 면으로 시작한다. 건설/협회/카드/동물/후원의 기존 명령과 보상 처리를 재사용한다. 반복 도중 사용한 카드를 이동하지 않으며 마지막 반복 후 한 번 이동한다. 종료 후 효과는 모든 반복이 끝난 뒤 실행한다.
- 같은 카드의 일반 행동 선택지는 반복마다 달라도 된다(예: 스냅 후 드로우). X 행동의 반복에는 일반 행동을 섞지 못한다. 한 번 이상 완료한 반복 사이에 END_REPEAT로 나머지를 포기할 수 있어 X 상한 등에서 막히지 않는다. 시작한 행동의 버리기/효과 선택 중에는 END_REPEAT를 거절한다. 추가 행동 안의 배수 반복도 부모 효과로 돌아간 뒤에야 실제 솔로 턴을 끝낸다.
