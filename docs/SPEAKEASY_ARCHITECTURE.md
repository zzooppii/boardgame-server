# 스피크이지 구현 경계

[규칙과 자료 확인](./SPEAKEASY_GAME_RULES.md)을 따른다. 현재 단계는 확인한 규칙의 순수 서버 모듈, 검증, 실제 웹에서 조작하는 화면·음향 미리보기다. **멀티플레이 기본판은 아직 활성화하지 않는다.**

## 책임

- `packages/shared/src/games/speakeasy`: 직렬화 가능한 공개 건물·화면 DTO, 입력 enum. 서버 전체 state나 덱 순서는 export하지 않는다.
- `apps/server/src/games/speakeasy/domain`: 지불, 영업, 건설·증축·인수, 생산, 운송, 판매, 보호, 수준 증가, 방어, 목표 조건, 지역/최종 정산. 순수 함수가 복제한 candidate를 만들며 실패하면 원본을 보존한다.
- `apps/web/src/features/speakeasy`: 지도 중심 React 화면, 개인판, 대상/결과 검토, 키보드·터치, 영업 상태와 주류 표시, 효과음, 모션 감소.
- 처음에는 홈의 별도 **개발 미리보기**로 접근한다. 공개 게임 종류·room state·게임 시작에 미검증 기본판을 추가하지 않는다. 미리보기는 대국이나 솔로 모드가 아니며 고정된 예시를 탐색한다.

경제 모듈 함수는 전체 행동을 완성하는 서비스가 아니라 검증 가능한 하위 계산이다. 서버에서 주입할 생산량·판매 단가·이동 그래프·배당표와 행동 권한을 인자로 받는다. 초기 설정, 카드·개인판 보너스, 악명 보상, 장소별 선택 큐는 아직 연결하지 않았다. 이 함수를 Socket.IO 입력에 직접 연결하면 안 된다. `nextSpeakeasyTurn`은 라운드 경계 분류이며 `round-lifecycle.ts`가 필수 운영 카드 뽑기와 레스토랑 수익·차례 정산을 처리한다.

## 차례와 라운드 종료

`domain/round-lifecycle.ts`는 `PLAYING → DRAW_OPERATION → PLAYING/ROUND_END → PLAYING/LUCIANO/FINAL_SCORING`을 관리한다. 서버의 검증된 설정에서 시작하며 운영 덱 순서와 손패를 내부에 보관한다. 레스토랑 명령은 인증 actor, gameId/revision, 현재 차례, 빈 위치와 필요한 본인 카드 수를 검증한다. 선택 위치의 즉시 영향력 참조와 다음 라운드 실제 차례 순서를 구분한다. 영향력 비용표의 미확인 값은 추가하지 않았다.

장소 행동을 끝내는 내부 hook 이후에는 운영 카드 뽑기를 생략할 수 없다. 클라이언트는 덱 종류만 고르며 서버가 맨 위 카드를 가져온다. 버린 카드는 해당 덱 아래로 돌려 전체 인스턴스 ID를 보존한다. `commitSpeakeasyRoundEconomy`는 서버에서 권한과 효과를 검증한 경제 함수 결과만 통합하는 내부 경계다. 클라이언트가 계산한 상태를 받는 API로 노출하지 않는다.

라운드 종료에서는 아래 줄의 방문 여부로 카지노 현금을 모든 플레이어에게 한 번 지급하고 차례를 확정한다. 마지막 라운드도 이 정산을 거쳐야 최종 점수를 반환한다. JSON 복원은 단계·차례 말·덱 종류와 ID·정산 기록의 일관성을 검사한다. 각 성공은 복제한 candidate를 검증하고 revision을 한 번 올리며 실패는 원본을 유지한다.

이 단계는 장소 권한, 카포 배치, 도우미/카드 보너스, 레스토랑의 서로 다른 두 선택 행동을 대신하지 않는다. 전체 게임 controller가 해당 효과를 먼저 해결한 뒤 내부 hook을 호출해야 한다. Luciano 완료 후 다음 막으로 연결하는 통합 controller와 Socket.IO 연결도 남아 있다.

## 마피아 충돌에서 지역 정산까지

`domain/luciano.ts`는 `REVEAL → DEFENSE → REVEAL … → COPS → PAYOUT → COMPLETE` 전이를 구현한다. 설정 함수는 서버에서 확정한 덱·공격 예정 구역·경찰 예정 구역·배당표를 받으며 실제 기본판 데이터를 생성하지 않는다. 인원별 공격 구역 수, 기존 마피아 중복, 구역 유효성, 카드 ID 중복을 검증한다.

각 공개는 한 구역에서 멈춘다. 그 구역에 건물이 있으면 차례순으로 방어 담당자를 정하고, 해당 플레이어는 자기 건물의 처리 순서를 선택할 수 있다. 요청에는 공격력이나 actor를 싣지 않는다. 인증 context의 actor, gameId와 revision, 현재 단계, 현재 방어 담당자와 대상 건물을 확인하고 비용·부하 소비·건물 교체·단계 변경을 함께 commit한다. 실패하면 원본과 revision은 유지한다. 같은 요청을 새 revision에 재적용할 수 없으며, transport의 성공 응답 재전송/idempotency receipt는 기존 Room 서비스에 연결할 때 추가한다.

다음 구역은 현재 구역을 완전히 해결한 뒤에만 공개한다. 이번 막에서 주점을 하나도 놓지 못한 신규 마피아는 제거 표시하고, 남은 신규 덱은 비공개 폐기 목록으로 옮긴다. 기존 마피아의 세력은 변경하지 않는다. 충돌 완료 후 예정된 경찰을 배치하고, 바뀐 영업 상태로 지역 지배를 계산해 금고에 한 번만 지급한다.

저장 가능한 내부 상태는 `parseSpeakeasyLuciano`로 검증·복원한다. `projectSpeakeasyLuciano`는 이미 공개한 마피아와 현재 선택 단계, 공개 건물 정보, 인증된 본인의 자금만 DTO로 재구성한다. 다음 마피아·버려지는 미사용 카드·다른 사람의 금고·손패·배당표 원본은 전송하지 않는다. 이 순수 복원 테스트는 실제 서버 재시작/Socket.IO 재접속 완성을 의미하지 않는다.

전체 게임 controller는 막 진입 시 동맹의 일회성 효과를 초기화하고, 단계 완료 후 다음 막의 구역·경찰 예약, 카포 회수와 차례 진행을 연결해야 한다. 해당 효과를 모든 동맹에 임의로 부여하지 않는다. 마피아 주점 24개가 부족하면 안전하게 중단하므로 관련 규칙 확인 전에는 이 모듈만으로 출시할 수 없다.

## 실제 게임 연결 시 필수 경계

기존 Room/Session/UoW/직렬화/idempotency를 재사용한다. 게임 종류별 concrete service와 projector를 추가하며 다른 게임을 리팩터링하지 않는다. 서버는 actor, room/game phase, gameId/revision/turnId와 현재 허용된 선택을 확인한다. 인증된 명령은 비용·부가 효과를 포함한 candidate가 유효할 때 한 번만 commit한다.

추가 선택의 담당자와 남은 효과 순서를 서버에 보관한다. 마피아를 한 구역씩 공개하는 처리와 방어 선택을 같은 상태 전이로 관리한다. 카드 열람이나 다른 사람의 선택 이후에는 전체 턴 rollback을 제공하지 않는다. 금고·손패·덱 순서·미래 마피아는 공개 projection에 넣지 않는다.

## 화면 및 소리

오리지널 주점 일러스트, 지도 구역별 건물·경찰·조직원·주류, 세 가지 구역권, 내 운영 수준, 선택 및 결과 패널을 사용한다. 정확한 본판 지도 자료 확보 전에는 **구역 개요**로 표시하며 운송 인접을 암시하지 않는다. 숫자를 이미지에 박지 않고 접근 가능한 텍스트로 렌더링한다.

선택은 짧은 나무 클릭, 건설은 두 번의 낮은 타격, 운송은 짧은 이동음, 판매는 금속성 화음, 보호는 부드러운 잠금음, 정산은 저음 피아노 화음을 사용한다. Web Audio는 사용자 제스처 이후 활성화하고 음량·음소거를 제공한다. 실제 대국은 초기·동일·역순·건너뛴 revision 및 재접속에서 이전 효과음을 다시 재생하지 않아야 한다. 시각 결과는 소리 없이도 이해할 수 있어야 한다.

## 남은 출시 작업

1. 규칙 문서의 전체 구성물 데이터 확인.
2. 검증된 catalog로 초기 설정, 장소별 복합 효과·막 진행을 연결하고 2/3/4인 완주 테스트.
3. 서비스·Socket.IO·개인별 projection과 대국 화면 연결 및 재접속/중복/이탈 테스트.
4. 기본판 카드별 회귀와 실제 다중 브라우저 완주, 모바일·키보드·음향 검증.

미리보기 검증을 실제 온라인 기본판 검증으로 대체하지 않는다.
