# 테라포밍 마스 아키텍처

## 최신 상태 — 기업시대·프렐류드 활성화

프로젝트 전체 조회는 기본 137장·기업시대 71장·프렐류드 프로젝트 7장을 포함한다. 게임 생성·재고 검증은 `corporateEra`와 `prelude`에 따라 프로젝트 137/144/208/215장, 일반 기업 10/12/15/17종을 고정한다. 프렐류드 35장은 별도 재고로 보존한다. 공개 game projection은 동일한 변형 값을 포함한다. 기존 `mars-base-v1`은 게임 계열 계약 버전으로 유지하며 기업시대 여부는 별도 필드로 나타낸다. 아래 단계별 미연결·준비 수량 기록은 구현 이력이다.

`mars:configure`는 방장·LOBBY·expectedRoomRevision과 인증 세션을 검증하고 기존 방 mutation 직렬화 및 idempotency transaction으로 설정을 저장한다. 게임 시작은 동일한 직렬화 경계에서 설정을 읽어 상태를 생성한다. 저장소는 설정과 게임 상태 변형의 불일치를 거절한다. 로비·게임 projection 및 재접속에서 설정을 보존한다. 영구 저장은 추가하지 않는다.

특수 카드 반응은 순수 domain 계층에서 효과를 생성하고 기존 서버 효과 큐에서 해결한다. UI는 서버 후보·이전/이후 수량을 표시하고 확정 명령만 전송한다. 카드 조건·대상·수량·지불·점수는 서버가 판정한다.


기존 Room/Session/Socket.IO/직렬 실행/멱등성 경계를 이용하는 `TERRAFORMING_MARS` 전용 구현이다. 게임 규칙은 `games/mars/domain`, 입출력·원자적 저장은 `application`, 비공개 상태를 플레이어별로 분리하는 코드는 `compatibility`에 둔다. 공유에는 공개 카드 정보와 직렬화 가능한 계약만 둔다.

서버가 선택 가능한 행동과 배치 칸, 비용을 계산하고 실행 시 다시 검증한다. 각 명령은 복제한 상태를 완전히 검증한 후 한 번만 저장한다. 효과 도중 추가 선택이 필요한 경우 서버 상태에 대기 선택을 저장한다. 클라이언트는 비공개 덱·다른 손패·서버 효과 큐를 받지 않는다. 재접속·오래된 revision·중복 요청은 기존 플랫폼과 동일하게 처리한다.

UI: 화성 지형을 중앙에 두고 상단 전역 지표와 자원, 하단 손패, 오른쪽 맥락별 행동 패널을 배치한다. 지도와 낸 카드를 전환하고 참가자별 공개 정보·업적·기업상을 확인한다. 클릭·터치·키보드 선택과 별도 확정으로 조작하며, 배치 후보와 예상 결과를 함께 표시한다.

일러스트는 imagegen으로 새로 생성한 지형 및 12장면 카드 atlas를 프로젝트에 저장해 사용한다. 아이콘과 타일은 읽기 쉬운 SVG/CSS로 표시한다. 효과음은 사용자의 첫 입력 뒤 Web Audio로 합성하며 음량·음소거를 제공한다. 서버가 확정한 연속 revision만 재생하여 재접속 시 과거 효과음을 반복하지 않는다. 모션 감소 설정에서는 이동 애니메이션을 줄인다.

출시 범위는 [TERRAFORMING_MARS_GAME_RULES.md](./TERRAFORMING_MARS_GAME_RULES.md)를 따른다. 영구 저장은 사용자 요청으로 개발 범위에서 제외한다. 기업시대와 프렐류드는 로비의 개별 플레이 옵션으로 활성화했다. [기업시대 이력](./TERRAFORMING_MARS_CORPORATE_ERA.md)과 [프렐류드 설계](./TERRAFORMING_MARS_PRELUDE.md)를 따른다.

## 기본판 조합 검증·손패 탐색 개선

수령 가능한 카드가 있을 때 동물·미생물 추가를 생략하던 동작을 수정했다. 기본판 규칙서 9쪽의 자원 수령 예외는 받을 카드가 없는 경우에만 적용한다. 회귀 테스트에서 오류를 먼저 재현한 뒤 수정했다.

손패 탐색은 `hand.ts`에서 검색·필터·정렬만 처리한다. 조건 충족 여부와 할인된 비용은 서버 `cardStatus`를 사용하며, 클라이언트에서 실행 허가를 새로 판정하지 않는다. 원본 손패 순서를 바꾸지 않는다. 낸 카드 요약의 보유 태그에서는 이벤트 태그를 제외하고 기업의 중복 태그를 포함한다. 미사용 행동 수는 비용을 지불할 수 있는 행동 수와 구분해 표시한다.

### 실제 브라우저 검증 재실행

별도의 로컬 테스트 서버와 Playwright가 필요하다. 기존 앱 의존성에는 추가하지 않는다. 서버 빌드 후 `PORT=3018 NODE_ENV=production node apps/server/dist/index.js`로 테스트 서버를 실행한 상태에서 다음을 실행한다.

```sh
MARS_BROWSER_URL=http://127.0.0.1:3018 node --test e2e/mars.browser.test.mjs
```

Playwright가 외부 런타임에 있으면 `PLAYWRIGHT_MODULE`에 모듈 경로를, 시스템 Chrome을 사용하려면 `MARS_CHROME_PATH`에 실행 파일 경로를 지정한다. 스크린샷은 실행마다 새 임시 디렉터리에 저장하고 경로를 출력한다. 테스트는 새 브라우저 세션 두 개와 새 방을 사용하며 기존 사용자 자격 증명을 읽지 않는다. 자동 실행은 로컬 서버 주소로 제한한다.

- 루트 타입 검사·빌드 통과. 전체 테스트 5,090개 통과(공유 133 / 웹 917 / 서버 3,885 / E2E 155). 이후 엔진 요약 및 접근성 이름을 포함한 웹 테스트 918개 재검증도 통과했다.

- 실제 브라우저 검증에서 다른 미리보기 서버와의 포트 충돌을 발견해 독립 포트로 분리했다. 선택 상자의 접근성 이름을 명시한 뒤 데스크톱·390px 모바일 시나리오가 통과했다.

## 지불·효과 해결 안내

`ActionFeedback.tsx`는 서버 projection의 지불 대기·배치 후보·효과 선택에 맞는 안내를 표시한다. 클라이언트에서 효과 큐나 완료 단계를 추측하지 않는다. 지불 입력 옆에는 해당 지불만 차감한 잔량을 표시하며, 카드 효과와 보너스가 포함되지 않았음을 명시한다.

행동 패널의 ‘마지막 내 자원 변화’는 동일한 플레이어의 연속된 서버 상태에서 보유 자원·생산량·TR의 이전 값과 이후 값을 비교한다. 타인의 행동으로 내 자원이 바뀌어도 표시한다. 변화가 없는 상태와 중복 상태는 마지막 내역을 유지하고, 첫 접속·재접속·누락된 상태·다른 게임 또는 플레이어로 전환하면 비교 내역을 지운다. 브라우저 메모리에서만 유지하며 대국 저장 기능은 추가하지 않는다.

### 안내 개선 검증 결과

- 루트 `typecheck`와 `build` 통과. 기존 공통 번들의 500kB 경고는 유지된다.
- 첫 `npm test`는 샌드박스의 로컬 포트 제한(`listen EPERM`)으로 실패했다. 포트 사용 권한으로 재실행한 전체 테스트 5,140개(공유 133 / 웹 928 / 서버 3,924 / E2E 155)는 모두 통과했다.
- 마스 웹 테스트는 8개다. 자원·생산량·TR 변화, 중복·누락·재접속 상태, 지불 취소 가능 여부, 배치·효과 안내를 포함한다.
- 실제 Chrome 두 세션의 손패·모바일 폭·키보드 배치·재접속·음소거 시나리오 통과. 지불 전 42 → 24 M€ 미리보기, 지불 후 −18 M€ 내역, 해양 배치 후 TR +1, 새로고침 후 과거 변화 미표시를 확인했다. 초기 브라우저 검증에서 일반 프로젝트의 취소 불가능한 지불을 추가 지불로 표현한 문구를 발견해 수정하고 재검증했다.

## 모바일 영역 이동과 키보드 배치

760px 이하의 진행 화면에는 지도·행동·손패 바로가기를 고정 표시한다. 바로가기는 해당 영역을 화면으로 이동하고 키보드 초점도 옮긴다. 지도 바로가기는 낸 카드·기업 상세를 보고 있더라도 지도 탭을 연다. 지불·효과 해결 중에는 행동 버튼의 문구가 현재 맥락을 알려준다. 바로가기 자체는 명령을 전송하거나 선택을 확정하지 않는다.

하단 여백은 고정 바와 기기의 safe area를 고려한다. 모션 감소 설정에서는 부드러운 스크롤을 생략한다. 지도에서 Tab으로 접근 가능한 칸은 서버가 제공한 배치 후보 중 현재 조작 가능한 칸으로 한정하며, 다른 칸의 설명은 접근성 트리에 유지한다. 지도 확대 선택과 배치 목록의 터치 영역은 최소 44px로 표시한다. 실제 휴대폰 및 보조기기 검증은 별도로 남아 있다.

모바일 브라우저 검증은 390px에서 영역별 이동과 초점, 지도 탭 복귀, 배치 후보의 Tab 순서, 지불·키보드 배치까지 확인한다. 320px에서는 가로 넘침 없음과 바로가기 버튼의 최소 44px 터치 영역을 확인하고, 이동 완료 뒤 뷰포트 스크린샷을 촬영한다. 화면 이동 중 촬영하면 빈 프레임이 잡힐 수 있어 초점 및 두 렌더 프레임을 기다리도록 검증 코드를 보완했다. Chrome 데스크톱 브라우저의 작은 뷰포트 검증이며 실물 모바일 기기 검증으로 취급하지 않는다.

### 모바일 이동 개선 검증 결과

- 루트 `typecheck`, `build`, `git diff --check` 통과. 기존 공통 번들 500kB 경고는 남아 있다.
- 루트 `npm test`: 공유 133개, 웹 931개 통과. 서버 3,924개 중 3,923개 통과, 기존 SNEAKY 실시간 부하 테스트 1개가 `Too little exercise: 144`로 실패했다. 기준을 변경하지 않고 해당 테스트만 단독 재실행하여 통과했다. 전체 실행에서의 실패는 간헐적 실패로 남겨두며 전체 최초 실행을 성공으로 표시하지 않는다.
- 위 실패로 루트 실행에서 중단된 공통 E2E를 별도로 실행하여 155개 통과했다. 마스 실제 브라우저 시나리오도 통과했다.
- 최초 브라우저 실행은 이전 미리보기 서버가 종료되어 연결 실패했다. 독립 로컬 서버를 새로 실행한 뒤 검증했으며 320px 스크린샷의 빈 프레임은 이동 완료를 기다린 재촬영으로 해소했다.

## 다인 동시 선택·재접속 검증 보강

3·4·5명의 Socket.IO 클라이언트가 동일 revision으로 초기 선택 또는 연구 구매를 동시에 제출하는 시나리오를 추가했다. 현재 정책은 같은 revision에서 한 명만 성공하고 다른 명령은 `STALE_GAME_REVISION`으로 거절하는 것이다. 각 참가자가 최신 상태에서 다시 확정하면 구매는 한 번만 반영되고, 이미 성공한 요청을 재전송해도 재구매하지 않아야 한다. 테스트는 구매 비용·손패 수·revision 증가·다른 사람의 손패 및 연구 카드 식별자 비공개·확정 후 재접속을 함께 검증한다. 실제 사람의 장기 플레이 평가는 별도로 남는다.

기존 재접속 검증에 지불 완료 후 배치 대기 중 다시 끊기는 경우를 추가했다. 후보·보유 자원이 복원되고 다른 참가자는 배치 선택을 받지 않으며, 같은 배치 요청을 두 번 보내도 해양·자원·TR이 한 번만 반영되는지 확인한다.

다인 검증은 연구 확정 후 재접속한 참가자를 포함해 실제 Socket.IO 명령으로 최종 정산까지 진행한다. 매 세대 연구, 일반 프로젝트·자원 전환, 지불·배치, 생산·마지막 녹지를 거쳐 전역 지표 완료와 모든 참가자에게 동일한 최종 결과가 전달되는지 확인한다. 자동 플레이 전략은 일반 프로젝트와 자원 전환 중심이며 모든 카드 조합의 검증이나 사람의 장기 플레이를 대신하지 않는다. 마스 통합 테스트 4개 단독 실행은 모두 통과했다.

검증: 루트 `typecheck`, `test`, `build` 및 `git diff --check` 통과. 전체 테스트는 5,159개(공유 133 / 웹 934 / 서버 3,937 / E2E 155) 모두 통과했다. 기존 공통 번들의 500kB 경고는 남아 있다. 이번 변경은 서버 통합 테스트와 문서이며 브라우저 화면·런타임 규칙은 바꾸지 않았다.

## 기업 선택·연구 오류 안내

초기 기업 선택과 연구 단계의 명령 오류는 선택 확정 버튼 근처에 표시한다. 같은 오류를 아래 행동 패널에 중복 표시하지 않는다. `STALE_GAME_REVISION`일 때는 서버 오류 코드를 유지하여 동시 제출에 따른 상태 변경과 재확정 방법을 안내한다. 로컬 카드 선택은 유지하며 자동으로 구매를 재전송하지 않는다. 응답 유실처럼 처리 결과가 불확실한 경우만 기존 요청 ID로 결과 확인 버튼을 제공한다. 이미 선택 완료 상태로 복원됐더라도 이 버튼은 대기 화면에 표시한다.

서버 회귀 검증은 초기 기업·자원·생산량 숨김, 전체 선택 완료 후 기업 공개, 본인 projection 복원, 지불 전 카드 선택 취소 시 자원·손패·특수 설계·행동 수 유지, 실패한 지불의 상태 불변을 확인한다. 브라우저 검증은 한 참가자의 상태 broadcast만 일시적으로 받지 않게 해 실제 서버의 stale 거절을 유도한다. 명령 응답과 상태 재조회는 정상 서버로 처리하며, 오류가 선택 화면에 보이고 선택이 유지된 상태에서 재확정되는지 확인한다.

검증 결과: 루트 `typecheck`, `test`, `build`, `git diff --check` 통과. 전체 테스트 5,163개(공유 133 / 웹 936 / 서버 3,939 / E2E 155) 모두 통과했다. 마스 도메인 26개와 웹 10개를 포함한다. 실제 Chrome 두 세션에서 지연된 상태 수신으로 초기 선택 거절을 재현하고 선택 화면의 안내·카드 선택 유지·재확정 성공을 확인했다. 기존 모바일 배치·재접속·음소거 시나리오도 통과했다. 공통 번들 500kB 경고는 남아 있다.

## 비공개 열람 카드 대기 상태

`cardChoice`는 서버 state에서 소유자와 `KEEP` 또는 `BUY` view를 저장한다. 카드 보존 검사는 덱·버림·각 플레이어 손패·연구·낸 카드에 이 대기 영역을 더해 검사한다. 효과 큐는 열람 중 정지하고, 게임 취소 시 보류 카드를 버림 더미로 옮긴다.

플레이어별 `privateState.cardChoice`는 소유자에게만 전달한다. `CHOOSE_CARDS`는 `choiceId`, 후보 `cardIds`, 선택적 `heat`를 받는다. 기존 `mars:act`의 인증·revision·turn·직렬 실행·멱등성 경계를 그대로 적용하고, 도메인에서 후보 소유·중복·선택 수·자원을 다시 검증한 뒤 한 번만 차감한다. 실패하면 후보와 자원·revision을 유지한다.

`CardChoicePanel.tsx`는 서버 후보를 표시하고 로컬 선택만 관리한다. 같은 선택 ID의 실패 응답은 선택을 유지하며, 새 선택 ID에서는 초기화한다. 전체 새로고침은 서버 후보만 복원한다. `cards.tsx`로 분리한 기존 카드 렌더러를 손패·열람 화면에서 공유한다.

선택 화면 전용 실제 브라우저 검증은 빌드 후 `node --test e2e/mars-private-choice.browser.test.mjs`로 실행한다. Playwright·Chrome 경로 환경 변수는 기존 브라우저 테스트와 같다. 별도 로컬 서버와 방을 만들고 종료하며, 테스트 프로세스 내부에서만 유효한 효과 대기 상태를 준비한다. 개발용 API나 기업시대 옵션은 추가하지 않는다.

## 같은 세대의 다음 프로젝트 할인

서버 `Player.nextCardDiscount`는 0 또는 8이다. 경제 함수는 영구 할인에 이 값을 더하고, 비용 검사·손패 projection·지불 요청 생성에서 같은 결과를 사용한다. 지불 전 취소·거절은 값을 바꾸지 않으며 카드 지불 성공 분기에서만 0으로 만든다. 새 카드의 효과를 처리하기 전에 초기화하므로 이후 발생한 할인은 보존된다. 세대 생산에서는 사용하지 않은 값을 초기화한다.

공유 `privateState.nextCardDiscount`는 본인의 상태만 전달하며, 클라이언트 명령으로 할인 값을 받지 않는다. `NextCardDiscount.tsx`는 할인 반영·사용 시점·만료를 설명한다. 별도 리소스 지출이나 재생 효과는 없으므로 기존 카드 실행 효과음을 그대로 사용한다.

## Mars University 손패 교환

공유 `MarsCardChoice`에 `EXCHANGE`를 추가했다. `cards`는 반드시 빈 배열이며 손패가 실제 후보다. 기존 `CHOOSE_CARDS`가 0장(생략) 또는 본인 손패 1장을 받으며, 열·중복·외부 카드 ID는 거절한다. 확정 전 손패는 이동하지 않으므로 카드 보존 검사와 취소 종료에서 중복 계산하지 않는다.

`science.ts`는 소유자와 새 카드의 과학 태그를 받아 순수 효과 목록을 생성한다. 카드 지불 후 해당 카드의 즉시 효과와 함께 서버 큐에 넣는다. 교환이 여러 번이면 각각 새 ID로 대기하고 최신 손패를 사용한다. 모든 선택이 끝난 뒤에만 기존 한 행동을 완료한다. 재접속·멱등성·동시성은 기존 `mars:act` 경계를 사용한다.

`CardChoicePanel.tsx`가 기존 카드 렌더러와 검색을 사용해 교환 대상을 보여준다. 선택된 카드를 검색으로 숨겨도 버릴 카드 이름과 해제 버튼을 유지한다. 획득 효과음은 손패 장수 증가 대신 새 카드 ID 유입으로 판정하여 교환과 연속 선택에도 반응한다.

## 자원 보호 판정

공유 `MarsPlayerPublic.protectedHabitats`와 서버 플레이어 상태에 보호 여부를 추가했다. `protectHabitats` 효과만 이를 활성화하며 클라이언트 명령으로 설정할 수 없다. 보호 상태는 세대 생산 시 초기화하지 않는다.

`marsCanRemoveResource`는 공격자·소유자·자원 종류·선택적 카드 종류를 받아 제거 허용 여부만 계산한다. 생산량 감소와 비용 지불은 이 함수를 사용하지 않는다. `effectsPossible`과 실제 `steal`·`removePlants` 후보 생성이 같은 함수를 호출해 실행 가능 표시와 최종 서버 검증을 일치시킨다. 위조된 대상 명령은 기존 후보 재계산·원자적 commit 경계에서 거절한다.

projection은 모든 참가자에게 보호 여부를 공개한다. 기업 현황의 표시와 엔진 요약은 이 값만 사용하며 클라이언트에서 보호나 공격 가능 여부를 새로 판정하지 않는다.

## 생산량 복제 효과 큐

`marsProductionBox`는 카드와 소유자의 타일에서 복제 가능한 효과만 추출한다. `copyProduction`의 사전 실행 가능 검사와 `copy-production:<tileId>` 후보 생성이 같은 추출 함수와 `effectsPossible`을 사용한다. 선택 명령을 처리할 때 후보를 다시 계산하므로 외부 카드·자원 부족·잘못된 ID는 mutation 전에 거절한다.

생산 감소는 대상을 확정한 뒤 기존 `payNegatives` 경계에서 한 번 적용하고, 남은 증가·상대 생산 감소는 기존 효과 큐로 해결한다. 카드 자체나 태그를 다시 플레이하지 않으며 카드 실행의 한 행동 안에서 마무리한다. UI는 서버 후보의 상세 설명과 별도 확정을 사용하고 `ActionGuide`가 복제 범위를 명시한다.

## 토지 예약

공개 `landClaims`는 `{spaceId, ownerId}` 목록이며 타일 목록과 분리한다. 서버는 중복·외부 소유자·해양 및 녹티스·타일과 중첩되는 예약을 거절한다. `claimLand`는 기존 효과 큐와 `TAKE` 명령의 예약 후보로 해결하고, 모든 배치 후보는 상대 예약 칸을 제외한다. 실제 타일 배치 시 예약을 제거한 뒤 기존 보너스·점수 규칙을 적용한다. 예약은 세대와 인메모리 재접속을 넘어 유지하며 영구 저장을 추가하지 않는다.

지도는 기존 지형 위에 기업 색상·번호 깃발과 점선 테두리를 그린다. 키보드·클릭으로 후보를 선택한 뒤 별도 예약 확정을 누른다. 공개 `CLAIM` 기록으로 기존 효과음을 사용하며 재접속 때 반복하지 않는다.

## 자원 제거·탈취

`attackStock`은 자원 종류·최대 수량·탈취 여부를, `removeCardResource`는 카드 자원 종류·최대 수량을 가진다. 서버는 기존 효과 큐에서 실제 보유량과 보호 상태로 대상·수량 후보를 만들며 TAKE 처리 시 다시 계산한다. 탈취는 한 원자적 상태 변경에서 상대 차감과 자신 증가를 함께 적용한다. 제거는 수입을 발생시키지 않는다. 모든 선택에 생략 후보를 제공한다. 확정된 공격은 공개 ATTACK 기록과 전용 효과음을 사용하고, 재접속에서는 소리를 반복하지 않는다.

## 카드 자원 종류와 점수 배율

전투기(`fighter`)를 카드 자원 종류로 추가하고 자기 카드 자원 추가 시 카드의 자원 종류와 효과의 종류가 일치하는지 검증한다. 실제 카드 수량은 기존 서버 소유 `resources`를 사용한다. `resourceScore`는 필요한 자원 수(`per`)와 획득 점수(`points`)를 분리한다. 기본판은 기존 분모를 `{per: 기존 값, points: 1}`로 변환하며 서버 최종 점수는 카드별로 묶음을 버림한 뒤 점수를 곱한다. UI 점수 문구와 자원 이름도 같은 정의를 읽는다. 기업시대 실행 카탈로그는 아직 활성화하지 않는다.

## 생산량 공격 선택

`marsCanReduceProduction`을 실행 가능 여부와 대상 후보의 공통 판정으로 사용한다. 생산량 감소는 보유 자원·서식지 보호와 분리하고 M€ -5 / 기타 0 하한을 적용한다. 자기 대상도 허용한다. 대상 확정은 기존 원자적 TAKE 경계에서 처리하며 공개 ATTACK 기록과 기존 공격 효과음을 사용한다. 클라이언트는 서버가 만든 변경 전후 값과 자기 대상 경고만 표시한다.

## 통합용 기업시대 카탈로그와 요구 조건

공유 `corporate-era-catalog.ts`는 인쇄 데이터에 준비된 즉시 효과·행동·지속 설명을 묶은 40장 목록과 아직 조립하지 않은 31장 ID를 제공한다. 이 목록은 실행 덱·`marsCard` 조회에 포함하지 않는다. 전체 활성화 전에 누락 카드의 규칙과 실행 카탈로그 어댑터를 완성해야 한다.

서버 `requirements.ts`는 전역 지표·태그·생산량·전체 도시·자기 녹지 요구 조건을 판정한다. 기본판의 기존 조건 표현을 어댑터로 변환하고, 기업시대의 구조화된 조건은 직접 평가할 수 있다. 전역 조건 완화는 기온에는 2°C 단위로, 산소·해양에는 1단위로 적용하며 태그·생산량·도시·녹지에는 적용하지 않는다. 게임 서비스는 지불 전 서버 상태와 기존 보유 태그 수를 전달한다.

경제·선택 카드 추가 조립 후 준비 목록은 48장, 미조립 목록은 23장이다. 지속 효과만 있는 카드도 빈 즉시 효과 목록과 명시적인 지속 설명으로 구성하며 기존 경제 계산기의 카드 ID에 연결된다. Business Network는 필수 시작 생산 감소와 별도 구매 행동을 모두 갖춘 정의로 구성한다. 이 준비 목록은 아직 실행 카탈로그와 분리되어 있다.

기본 효과·행동 추가 조립 후 준비 58장·미조립 13장이다. `corporate-era-standard.ts`는 기존 효과 타입으로 완전한 즉시 효과·행동을 구성하며 준비 카탈로그에서 인쇄 정보와 결합한다. 점수·태그 전용 카드 2장은 명시적인 빈 효과 목록을 가지며 실행 덱에는 여전히 포함하지 않는다. 검증용 효과 fixture는 실제 기업시대 카드 등록을 대신하지 않는다.

## 에너지 생산 이전의 원자적 처리

`transferEnergyProduction`은 고정 1단계 에너지 생산 이전을 표현한다. `production-attacks.ts`의 순수 대상 함수는 양의 생산자만 반환하고 전체 0일 때만 actor를 반환한다. TAKE 후보를 서버가 재계산하며 감소·증가를 하나의 resolve에서 함께 반영한다. 자기 대상은 최종 변화 0이다. 새 효과를 저장 상태 런타임 스키마와 설명에 추가하고 UI는 서버 후보와 변화를 표시한다. 준비 카탈로그는 60장·미조립 11장이며 실제 덱은 기본판을 유지한다.


## 프렐류드 통합

`prelude` 설정과 `PRELUDE` 실행 단계를 추가했다. 35장 전용 재고와 비공개 후보를 서버가 보존하며 선택 이후의 카드 실행은 기존 지불·효과 큐·원자적 commit 경계를 사용한다. 공용 DTO의 선택 카드·미생물 지불·단계 확장 및 기존 대국과의 관계는 [프렐류드 설계](TERRAFORMING_MARS_PRELUDE.md)에 기록한다. `rulesVersion`은 기존 계약 계열을 유지하고 실제 덱 구성은 두 확장 flag로 구분한다.


## 카드 인쇄 조건 가독성 보완 (2026-09-16)

`apps/web/src/features/mars/requirements.ts`는 기본판·기업시대·프렐류드의 공개 카드 정의를 한국어 인쇄 조건으로 표현한다. 기온(°C), 산소(%), 해양·태그·도시 개수, 생산량과 상한/하한을 구분한다. 카드 앞면과 상세 화면이 같은 표현을 사용하므로 초기 구매·비공개 카드 선택에서도 조건을 확인할 수 있다. 조건 없는 카드에는 빈 조건 영역을 만들지 않는다.

이는 표시 전용 함수다. 기업·카드 효과에 의한 조건 완화, 와일드 태그 사용과 최종 실행 가능 여부는 기존 서버 `cardStatus`와 명령 검증을 따른다. 카드 버튼의 접근성 이름에도 인쇄 조건을 포함한다. 조건 띠는 카드 높이에 맞춰 줄바꿈하며 효과·점수 내용을 자르지 않는다.

카드 그림/목록 전환 시 태그 조건을 유지하고 필터 초기화 및 다른 기업 전환 시 모든 태그로 돌아간다. 서버 명령을 전송하지 않는다. 40장 Chrome 시나리오에 태그·최근순·이름 검색 조합, 일치하는 카드가 없는 경우, 보기 전환, 전체 초기화와 상태 불변 검사를 추가한다.

모바일 캡처에서 긴 선택 상자가 도구 영역 오른쪽을 넘어 잘리는 현상도 발견했다. 도구 영역의 입력·선택 상자에 `min-width: 0`을 지정해 두 열 안에서 줄어들도록 한다. 같은 스타일을 사용하는 손패 필터에도 적용된다. 전체 페이지 가로 너비 검사만으로 잡히지 않던 문제이므로 각 입력·선택·버튼의 실제 경계가 도구 영역 안에 있는지도 Chrome에서 검사한다.

검증: 경계 검사가 수정 전 실패하고 수정 후 통과했으며, 320px 캡처에서 선택 화살표까지 표시됨을 확인했다. Chrome 태그·검색·보기 전환·초기화 및 기존 재접속·효과음 시나리오 통과. 최신 마스 변경을 반영한 격리 복사본에서 루트 타입 검사·빌드·테스트 통과. 공유 145개·웹 1,021개·서버 4,212개·공통 E2E 155개, 총 5,533개에서 실패·취소·미실행 0개다. 기존 공통 번들 500 kB 경고는 유지된다.

## 기업 선택과 공개 기업 정보

`CorporationIdentity`가 기업 이름·인쇄 태그·효과 설명과 기존 그림을 표시한다. 광업협동조합의 건물 태그 두 개 등 반복 태그는 유지하며 태그가 없으면 명시한다. 기업 선택·내 기업·공개 기업 상세에서 같은 컴포넌트를 사용한다. 그림은 atlas의 3:2 비율을 유지한다. 초기 구현은 기존 그림을 사용했으며, 이후 에코라인·헬리온·광업협동조합·타르시스 공화국은 전용 그림을 연결했다. 제작·검증 범위는 [기업 일러스트](TERRAFORMING_MARS_CORPORATION_ART.md)에 기록한다.

`CorporationChoice`는 선택 화면에만 시작 자금을 표시한다. 공개 기업 정보에는 시작 자금을 표시하지 않아 현재 보유금과 혼동하지 않게 한다. 선택 상태는 기존 `aria-pressed`와 테두리에 더해 `✓ 선택됨` 문구로 안내한다. 기업 선택 자체는 로컬 상태이고 기존 별도 확정 버튼을 눌렀을 때만 서버 명령을 보낸다. 기업 효과·시작 자원·기업 배분 규칙은 변경하지 않는다.

검증: 초보자·기본판·기업시대·프렐류드의 전체 기업 렌더링, 시작 자금, 반복 태그를 검사했다. Chrome에서 키보드 선택·별도 확정 전 revision 불변, 기업 선택 및 공개 정보의 320px 캡처, 그림 3:2 비율을 확인했다. 최신 마스 변경을 반영한 격리 복사본의 루트 타입 검사·빌드·테스트 통과. 공유 145개·웹 1,023개·서버 4,212개·공통 E2E 155개, 총 5,535개에서 실패·취소·미실행 0개다. 기존 공통 번들 500 kB 경고와 실기기·스크린리더 검수는 남아 있다.

## 음소거 해제 시 이전 음량 복원

기존 소리 켜기 버튼은 사용자가 고른 음량과 무관하게 30%로 바꿨다. 현재 음량과 마지막 양수 음량을 함께 관리해 음소거 해제 시 이전 음량으로 복원한다. 슬라이더를 0으로 내리는 경우에도 마지막 양수 음량을 유지한다.

기존 `mars-sound-volume` 키는 유지하고 브라우저 선호 설정 `mars-sound-restore-volume`을 추가한다. 기존 음량만 저장된 경우 해당 양수 음량을 사용하고, 기존 음소거 상태에 복원 정보가 없으면 30%를 사용한다. 빈 값·잘못된 값은 기본값을 사용하며 범위를 0–100으로 제한한다. 저장소 접근 실패 시 기본 설정으로 작동한다. 이는 효과음 선호 설정이며 대국 상태 저장은 아니다.

서버 명령·게임 판정·효과음 패턴은 변경하지 않는다. 기존 master gain의 음소거와 재접속 시 과거 소리 미재생 동작을 유지한다. Chrome 회귀는 65% 설정→음소거→새로고침→소리 켜기에서 수정 전 30%로 돌아가는 실패를 재현한다.

수정 후 첫 Chrome 실행은 음량 검사 전 기존 프렐류드 해양 배치에서 `.tm-hex.legal`이 `aria-disabled=true`로 남아 15초 시간 초과가 발생했다. 코드를 바꾸지 않은 재실행은 전체 시나리오가 통과했다. 당시 원인을 확정하지 못해 별도 분석 항목으로 남겼으며, 후속 재현·수정은 아래 프렐류드 연속 배치 절에 기록한다. 최종 실행에서 음소거 중 미리듣기 oscillator 미생성, 새로고침 후 음소거 및 65% 복원, master gain 0.65 반영, 슬라이더 20→0 이후 20% 복원, 과거 소리 미재생과 game revision 불변을 확인했다.

최신 마스 변경을 반영한 격리 복사본에서 루트 타입 검사·빌드·테스트 통과. 공유 145개·웹 1,025개·서버 4,212개·공통 E2E 155개, 총 5,537개에서 실패·취소·미실행 0개다. 기존 공통 번들 500 kB 경고는 유지되며 실제 기기·청음 검수를 대신하지 않는다.

## 프렐류드 연속 배치 브라우저 동기화

위 음량 검사에서 기록한 프렐류드 시간 초과를 기본 시드 11로 재현했다. 대규모 대수층의 첫 해양을 1-2에 놓은 직후 서버는 revision 8의 두 번째 배치 후보 1-4를 제공했다. 브라우저 역시 연결 상태와 다음 후보가 정상이었지만, 테스트의 `.tm-hex.legal.first()` 클릭은 이전 화면에서 찾은 1-2 요소의 활성화를 계속 기다렸다. 해당 요소는 첫 해양이 놓인 칸이라 비활성이 정상이다.

테스트를 서버 후보의 `targetId`에 해당하는 칸을 찾도록 수정했다. 실제 클릭과 별도 확정은 유지하고, 선택한 칸의 commit·타일 수 증가·해양 수 증가 및 대규모 대수층의 두 번 배치를 추가 검사한다. 게임 코드와 서버 판정은 바꾸지 않는다.

브라우저 테스트의 마스 난수 port에 재현 가능한 시드를 주입한다. 기본값은 11이며 `MARS_BROWSER_SEED`로 0–4294967295 정수를 지정할 수 있다. 생산 환경 난수는 변경하지 않는다. 기본 시드에서는 두 번의 해양 배치가 실제로 실행됐는지 필수 검증한다.

실패 시 참고할 `diagnostics.json`과 마지막 화면을 서버 종료 전에 저장하도록 순서를 바꿨다. 기존 캡처는 종료 뒤였으므로 연결 끊김 표시가 실패 원인처럼 보일 수 있었다. 진단 파일에는 시드·진행 단계·후보·서버 revision·공개 행동 기록·화면 안내를 기록하고, 세션 자격 증명이나 전체 저장 레코드는 기록하지 않는다.

검증: 같은 시드 11에서 수정 전 시간 초과를 재현했고 수정 후 Chrome 전체 시나리오가 3회 연속 통과했다. 세 번 모두 대규모 대수층 해양 두 칸의 실제 commit을 검증했다. 최신 마스 변경을 반영한 격리 복사본의 루트 타입 검사·빌드·테스트 통과. 공유 145개·웹 1,025개·서버 4,212개·공통 E2E 155개, 총 5,537개에서 실패·취소·미실행 0개다. 기존 공통 번들 500 kB 경고는 유지된다.
